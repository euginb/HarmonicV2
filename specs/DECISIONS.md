# DECISIONS — журнал решений и открытые вопросы

Решения нумеруются `Д-##` общие для проекта, либо `Д-##.####` относящееся к конкретному станку, группируются по типам и не переписываются: при отмене решение помечается как
отменённое со ссылкой на заменившее. Открытые вопросы — `OQ-##`, закрытые
остаются в списке с пометкой и ссылкой на решение.

## Принятые решения

| №    | Решение | Ревизия |
|------|---|---------|
| Д-01 | Порядок работ: исполнитель готовит патчи по плану CODE_PLAN.md (пункты CP-## дублируются `TODO(CP-##)` в коде); заказчик запускает `main.py` и докладывает результат; пункт закрывается только после прогона | rev 0   |
| Д-02 | Маркировка станков `S<тип><№>-<компоновка>` по SPEC-01 | rev 0   |
| Д-03 | Классы точности закладных K1/K2/K3 и способы монтажа M1–M4 по SPEC-02 | rev 0   |
| Д-04 | Закладные — лазерный раскрой из 2–3 листов; жёсткость рёбрами/прокатом; под рельсы — сегменты с зазором 10 мм | rev 0   |
| Д-05 | Основное формообразование — ЭЭС, фрезерование вспомогательное; перелитой слой снимается ЭХП | rev 0   |
| Д-06 | Полярная схема обработки: контур круглых деталей по X+C, без контурного хода по Y | rev 0   |
| Д-07 | Данные производителей только из `specs/*.json`; компоновка узлов — относительными правилами, не абсолютными координатами | rev 0   |
| Д-08 | Редуктор ПТК: 4 ряда, фазировка 0°/90°/180°/270°, Øнар ≤110, u = 10…100 | rev 0   |
| Д-09 | Основная компоновка — HMC (SM-1-HMC, SE-1-HMC); VMC (SM-1-VMC, SE-1-VMC) рассчитывается параллельно для сравнения. Компоновка входит в код станка и во все производные имена (спецификация, JSON-дерево, CAD, ID узлов), поэтому варианты не конфликтуют. Правила — SPEC-01, `egm/naming.py` | rev 0   |
| Д-10 | Каталожный номер пары рельс+каретка: `EGC-HG-<тип><размер><нагр><крепл>-<класс>-<натяг>[-T]`, напр. `EGC-HG-H20CA-P-ZA` = каретка HGH20CAZAP + рельс HGR20R; `-T` — рельс HGR..T (крепление снизу). Пары — нераземные (matched set). Номера присваивает `egm/catalog.py` | rev 0   |
| Д-11 | Схема ПТК: жёсткое колесо неподвижно, выход на сепаратор, n = z − 1, u = z. Одноступенчатый расчёт — только u = 10…100; для u > 100 калькулятор не считает и рекомендует двухступенчатую схему u = u1·u2 | rev 0   |
| Д-12 | ИИ читает репозиторий через GitHub REST API: `/repos/euginb/HarmonicV2/commits` (база патча — последний sha), `/git/trees/<sha>?recursive=1` (состав), `/contents/<путь>?ref=<sha>` (содержимое в base64, крупные файлы — по частям). raw.githubusercontent.com для крупных файлов отдаёт сжатый ответ, который инструмент ИИ может не прочитать | rev 0   |
| Д-13 | Правило «≥3 строк контекста» снято: `tools/fix_diff.py` сверяет hunk с рабочим деревом и добирает контекст сам. Контекст, присутствующий в патче, обязан совпадать с файлом дословно | rev 0   |
