# HarmonicV2 — порядок работы с зеркалом в AI Drive

Дополнение к `README.md` (раздел «Правила взаимодействия с ИИ»). GitHub —
первоисточник истины; зеркало в AI Drive — рабочая копия для агентов с
песочницей (Super Agent). Дисциплина spec-first, решения `Д-##`, план `CP-##`,
формат unified diff — без изменений.

## Хранилище

| Объект | Путь в AI Drive | Роль |
|---|---|---|
| Зеркало репозитория | `/HarmonicV2-main.zip` | рабочая копия; перезаписывается по фиксированному пути при синхронизации; внутренний id может смениться — актуальная ссылка агент выдаёт в ответе на синхронизацию |
| Этот файл | `/HarmonicV2-workflow.md` | порядок работы + журнал синхронизаций |
| Патчи (unified diff) | `/HarmonicV2-patches/` | выдача изменений агентом; один файл — один патч, папка не затирается при синхронизации |

Архив — стандартный GitHub-архив ветки `main` (корневая папка `HarmonicV2-main/`,
без `.git`), поэтому базовый коммит зеркала фиксируется в журнале ниже.

Перед работой агент сверяет sha последнего коммита

если различаются — сначала синхронизация (п. 3 цикла).

## Почему зеркало, а не чтение через GitHub API

- файлы читаются целиком — без base64 по частям и лимита ~10 КБ у raw;
- работает grep по всему дереву и структурная навигация;
- в песочнице можно запускать код: `python main.py` (проверки code-first),
  `python tools/fix_diff.py p.diff` и `git apply --check` для самопроверки
  патча — того, что README требует перед наложением;
- GitHub API остаётся для истории коммитов и сверки актуальности.

## Зависимости в песочнице

- Прогон `main.py` (проверки code-first) использует только стандартную
  библиотеку Python — работает в песочнице без установки.
- Дополнительные библиотеки под задачу ставятся в песочнице (pip, venv).
  Проверено на cadquery 2.8.0 (потребность CP-05): импорт ~4 с, булевы
  операции и экспорт/обратный импорт STEP — доли секунды; бюджет песочницы
  ~20 ГБ диска и ~1,3 ГБ RAM.
- Песочница эфемерна: установленный venv не переживает пересоздание среды —
  CAD-задача начинается с переустановки зависимостей (~минута). Перечень
  зависимостей проекта фиксируется в репозитории (`requirements.txt`) при
  CP-05.
- Тяжёлые сборки и расчёты — по-прежнему локально у заказчика (Д-01):
  песочница верифицирует механику, а не заменяет рабочий прогон.

## Цикл работы агента (Super Agent)

1. **Старт задачи.** Скачать `/HarmonicV2-main.zip` из Drive, распаковать,
   читать `README.md`, `specs/DECISIONS.md`, `specs/CODE_PLAN.md`, `reports/`
   и нужные спецификации (Д-12, Д-15 — теперь с зеркала). После принятия
   патча `context-bundle_base2031649.diff` стартовый контекст собирается
   скриптом: `python tools/context_bundle.py --sha <base> <ключи задачи>`.
2. **Актуальность.** Сверить sha последнего коммита с журналом; если GitHub
   ушёл вперёд — синхронизация и продолжение уже по свежей копии.
3. **Синхронизация (после мержа пользователя).** Скачать архив ветки `main`
   (codeload), заменить `/HarmonicV2-main.zip` в Drive перезаписью на месте,
   дописать строку в журнал (sha, дата).
4. **Работа.** Полный доступ к файлам: чтение целиком, grep, запуск
   `python main.py` для проверки расчётов; правки готовить как unified diff.
5. **Самопроверка патча.** На распакованном зеркале:
   `python tools/fix_diff.py p.diff` → `git apply --check` (README, п. 5);
   отдавать пользователю только патч, прошедший проверку.
6. **Выдача.** Unified diff по правилам README (первая строка
   `# base: <sha>, CP-##`, контекст дословный и т.д.); выгрузить патч файлом
   в `/HarmonicV2-patches/` (раздел «Выдача патчей» ниже); при желании —
   обновлённые файлы целиком отдельными файлами (не вместо патча).
7. **После мержа.** Пользователь просит «синхронизируй зеркало» — выполнить
   п. 3 и проставить статусы «применён» в журнале патчей.

## Выдача патчей (unified diff)

Канал выдачи изменений — файл в AI Drive, а не вставка в чат: файл
переносится байт-в-байт, его не портят переносы строк и экранирование
маркдауна, и `git apply` принимает его без ручной чистки.

1. **Папка.** `/HarmonicV2-patches/` в корне Drive; при отсутствии создаётся
   агентом автоматически. Содержимое при синхронизации зеркала не удаляется.
2. **Имя файла.** `CP-##_<краткое-имя>_base<7 знаков sha>.diff`
   (например `CP-21_ptk-range_base2031649.diff`); если пункт код-плана не
   назначен — `<краткое-имя>_base<7 знаков sha>.diff`. Краткое имя —
   строчными латинскими буквами, цифры и дефис.
3. **Содержимое.** Стандартный unified diff по правилам README: первая
   строка `# base: <полный sha>, CP-##`, UTF-8 без BOM, LF.
4. **Ответ агенту.** В чате — прямая ссылка на файл в Drive и краткая сводка:
   CP-##, base sha, список затронутых файлов, результат
   `git apply --check`. Полный diff дублируется в чат только по просьбе.
5. **Дополнительно.** По просьбе пользователя те же изменения можно выдать
   и обновлёнными файлами целиком — в ту же папку, суффикс `_files`.
6. **Журнал.** Каждая выдача добавляет строку в «Журнал патчей» ниже;
   статус меняется на «применён» после push пользователя (при синхронизации).

## Детерминизм выборки контекста

Принцип: контекст выбирает механика, осмысляет — LLM. Уровни:

1. **Фиксированный пол чтения.** Любая сессия начинает с одного и того же
   набора: README, specs/DECISIONS, specs/CODE_PLAN, specs/CANCELLED,
   reports/checks.md (с зеркала). Список меняется только правкой этого файла.
2. **Ключ → файлы, не «смысл» → файлы.** Первичный поиск — по
   идентификаторам (Д-##, CP-##, OQ-##, X-##, SPEC-##, CAT-##, INS-##).
   После принятия патча `context-bundle_base2031649.diff` — командой
   `python tools/context_bundle.py --sha <base> <ключи и пути…>`:
   одинаковый ввод даёт байт-в-байт одинаковый bundle, код выхода 3 — ключ
   не найден. Семантический поиск «по смыслу» — только дополнением к bundle.
3. **Pinned base.** Задача всегда называет base sha (локальный
   `git rev-parse HEAD`); чтение — только из этого состояния зеркала;
   GitHub — только для сверки актуальности. Одинаковые base + ключи дают
   одинаковый контекст независимо от разговора.
4. **Декларация контекста.** Ответ агента открывает таблица «файл (base
   sha) — зачем в контексте»; прочитанное сверх bundle помечается
   «доп. чтение» — недетерминированная часть всегда видима.
5. **Предел механизма.** Детерминирован адресуемый контекст (пол, ключи,
   base); смысловое сужение остаётся за LLM — его поверхность ограничена
   п. 1–4 и видима в п. 4.
6. **Граница применимости.** Механизм действует в инфраструктуре Genspark
   при подключённом AI Drive: зеркало, синхронизация и канал патчей —
   функции AI Drive. Вне этой инфраструктуры — резервные пути Д-12/Д-15;
   `context_bundle.py` исполним локально, но без зеркала и канала патчей
   работает лишь как локальный сборщик bundle у заказчика.

## Правила для пользователя

- после каждого `git apply` + `commit` + `push` написать агенту:
  «синхронизируй зеркало HarmonicV2» — он обновит зеркало и отметит
  применённые патчи в журнале;
- забирать патч файлом из `/HarmonicV2-patches/` по ссылке из ответа агента
  (не копировать diff из чата — файл надёжнее);
- задачу начинать с указания работать по зеркалу и базовым sha
  (локальный `git rev-parse HEAD`): «Работаем с HarmonicV2: зеркало
  `/HarmonicV2-main.zip`, порядок `/HarmonicV2-workflow.md` в AI Drive,
  база <sha>: <задача> (CP-##)»;
- AI Chat (без песочницы) продолжает читать через GitHub API по Д-12/Д-15 —
  прежние инструкции в чате сохраняются как резервный путь.
- для модели в AI Chat артефакты контекста — bundle по ключам
  (`tools/context_bundle.py`) или `AUDIT_BUNDLE.md` (`tools/make_audit_bundle.py`),
  порядок — `instructions/INS-90_AUDIT_BUNDLE.md` (Д-26), режимы —
  `instructions/README.md` §2; плюс файлы, приложенные к сообщению;
  файлы читаются моделями с `raw.githubusercontent.com` (pinned к base sha);
  ссылки AI Drive моделям не передаются.

## Что остаётся неизменным

- запись в репозиторий — только человек: агент выдаёт патч, пользователь
  применяет (`git apply`), коммитит и пушит;
- spec-first: технология и методики правятся напрямую в `specs/`;
- code-first: числа — в коде и `specs/*.json`, результат — прогон `main.py`;
- формат патчей и `tools/fix_diff.py` — без изменений.
