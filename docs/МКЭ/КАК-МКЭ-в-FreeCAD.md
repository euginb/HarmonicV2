# МКЭ в FreeCAD: настройка и регламент работы

Статус: **рабочий документ** (2026-11-27, rev16.0, CP-138, Д-154). Постановки расчётов и
критерии приёмки — `docs/МКЭ/ТЗ-МКЭ-ПТК.md`. Здесь — как получить работающий решатель и как
встроить расчёт в наш процесс, чтобы результат не устаревал молча.

## 0. Короткая проверка: готов ли FreeCAD считать

FreeCAD сам не решает — он пишет входной файл CalculiX, запускает `ccx`, читает результат.
Поэтому проверяются три вещи: `ccx`, мешер, само соединение.

В терминале:

```bash
ccx                  # должно ответить: Usage: CalculiX.exe -i jobname
gmsh -info           # версия и сборка; GUI не нужен, достаточно, что бинарник есть
```

Если `ccx` не найден, FreeCAD не поможет — сначала ставится решатель.

В FreeCAD: **Правка → Настройки → FEM**:

| Вкладка | Что выставить |
|---|---|
| CalculiX | галка «Искать в известных каталогах»; если `ccx` в нестандартном месте — снять галку и указать полный путь |
| Gmsh | галка «Искать в известных каталогах» либо путь к `gmsh(.exe)` |
| Netgen | **не нужен**. Gmsh достаточно; Netgen только добавляет проблем с зависимостями |

Финальная проверка — штатный пример **FEM CalculiX Cantilever 3D**: он входит в поставку
FreeCAD (с версии 0.17). Открыть, «Solve → Run», дождаться поля перемещений. Если пример
считается — решатель готов, и любая дальнейшая ошибка уже в постановке, а не в установке.

Проверить версию:

```python
import FreeCAD; print(FreeCAD.Version())
```

(консоль Python в FreeCAD: Вид → Панели → Консоль Python).

## 1. Установка по платформам

**Windows.** Пакеты с сайта FreeCAD **уже включают Gmsh и CalculiX** — дополнительно ставить
ничего не надо. Более свежий `ccx` можно взять на официальном сайте CalculiX
(https://www.dhondt.de/), архив вида `calculix_2.22_4win.zip`; распаковать и указать путь в
настройках FEM.

**Linux.** Пакеты в репозиториях: `calculix-ccx`, `gmsh` (и, при желании, `netgen`).
В Ubuntu проще подключить PPA `freecad-stable` — он содержит и FreeCAD, и `ccx`, и `gmsh`
свежих версий:

```bash
sudo apt-get install calculix-ccx gmsh
```

**Известная ловушка Linux:** старые сборки `ccx` линкуются с `libgfortran.so.4`, которого нет
в новых выпусках Ubuntu (там только `libgfortran5`). Признак — `ccx` падает при запуске,
`ldd /usr/bin/ccx` показывает «not found». Варианты: поставить `calculix-ccx` из репозитория
дистрибутива (обычно 2.17), либо собрать свежий `ccx` скриптом с feacluster.com. Проверять
именно запуском `ccx`, а не наличием файла.

**AppImage/Flatpak.** В них `ccx` и `gmsh` могут быть внутри, но не видны снаружи. Тогда
ставятся системные пакеты, а в настройках FEM путь указывается явно.

## 2. Единицы — до первого расчёта

CalculiX не имеет размерностей: числа должны быть в **согласованном наборе**. Наш набор —
**мм, Н, МПа, т, с**. Отсюда:

| Величина | Значение | Частая ошибка |
|---|---|---|
| Модуль упругости | 210 000 | 210 (это ГПа → получите деформации ×1000) |
| Плотность | 7.85e-9 т/мм³ | 7850 кг/м³ (даст силы инерции в 10¹² раз больше) |
| Момент | 1.1e6 Н·мм для 1100 Н·м | 1100 (это Н·м → занижение в 1000 раз) |
| Сила на тело | 416 Н при 1100 Н·м | — |
| Напряжение | МПа | — |

Материал задаётся в FEM → «Материал для твёрдого тела»: E, ν, ρ. Для ШХ15 и 40Х значения
берутся из `specs/materials.yaml`, а не из памяти; в отчёте указывается, откуда взято.

## 3. Порядок расчёта (на примере Р-1, венец)

1. **Геометрия.** Из `egm/cad` экспортируется STEP детали `.01`. Импорт в FreeCAD
   (File → Open). Проверить: тело — одно, замкнутое (`Part → Check geometry`), единицы мм.
2. **Упрощение.** Снять фаски и галтели, кроме ножек зубьев и пазов — они и есть концентраторы.
   Если геометрия режется плоскостями симметрии — вырезать сектор (90° для венца) и проверить,
   что рез не проходит через тело/зуб.
3. **Контейнер анализа.** Переключиться на верстак **FEM** → «Анализ» (Analysis). Внутрь
   складываются материал, сетка, ГУ, нагрузка, решатель — иерархия видна в дереве.
4. **Материал.** Solid material → E 210000, ν 0.3, ρ 7.85e-9. Для контактных постановок —
   добавить нелинейный материал только если считаете пластику (по ТЗ — не считаете).
5. **Сетка.** Mesh → «Gmsh». Максимальный размер элемента = толщина стенки / 4 (для 14.05 мм —
   3.5 мм); порядок элементов — **второй** (C3D10). Затем `MeshRegion` на зоны контакта
   (0.3…0.5 мм) и на ножку зуба. Проверить «Mesh → Display information»: число узлов и
   элементов записать в отчёт.
6. **Закрепление.** Constraint fixed — по боковым граням торцевых зубьев (Д-152). Второй
   вариант — контакт с жёсткой плитой: считается отдельно, оба результата в отчёт.
7. **Нагрузка.** Constraint force — по площадке контакта, направление тангенциальное.
   Практика: расщепить поверхность контакта на грани (Part → Split) и приложить силу к грани,
   а не к точке. Сила на тело при 1100 Н·м — 416 Н (R_Σ 82.55).
8. **Симметрия.** На плоскостях реза — Displacement: перемещение по нормали = 0 (две
   плоскости для сектора 90°). Для сектора 45° добавляется ещё одна пара.
9. **Решатель.** Solver CalculiX (ccx tools): тип анализа — статика, «Write .inp» включён.
   «Solve → Run». Смотреть лог: `*ERROR` в `.out` — расчёт не состоялся, `*WARNING` — читать.
10. **Результаты.** Pipeline from result → Warp (масштаб 1:1, не «усиление ×100» для отчёта) →
    von Mises. Съём по пути: `Data along line` через стенку/пояс; для сечений — `Section print`.
    Максимум по всей модели **не брать** — у заделки сингулярность.

## 4. Типовые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `ccx` не запускается, «not found» при `ldd` | нет `libgfortran.so.4` | пакет из дистрибутива или сборка свежего `ccx` |
| Solve мгновенно «Done», результата нет | не найден бинарник | Правка → Настройки → FEM → указать путь |
| Перемещения порядка 10⁶ мм | Е в ГПа или плотность в кг/м³ | привести к мм-Н-МПа |
| Напряжение 10⁴ МПа у отверстия | сингулярность у ребра/заделки | сгустить сетку и снимать по пути на расстоянии 1–2 элементов от кромки |
| Расчёт «не сходится» на контакте | контакт задан на несовпадающих поверхностях, зазор > 0 | проверить зазор, включить «firm» контакт, уменьшить шаг |
| Результат есть, но сумма реакций ≠ нагрузке | нагрузка приложена к грани, вырезанной сектором | перенести нагрузку внутрь сектора |
| Поля «рваные», пила по контуру | линейные тетраэдры | второй порядок (C3D10) |

## 5. Воспроизводимость: `.inp` — главный артефакт

FreeCAD-модель (`*.FCStd`) бинарная, тяжёлая и плохо диффится. Но решатель работает с
текстовым `.inp`, и именно он определяет расчёт.

Регламент:

1. Постановка собирается в GUI (быстро), затем **Solver → Write .inp** — файл сохраняется
   рядом с моделью.
2. `.inp` коммитится в git. Его можно прочитать, сравнить, отдать на ревью, прогнать заново
   **без FreeCAD**:

```bash
ccx -i job          # читает job.inp, пишет job.frd/.dat/.out
```

3. Если постановка меняется часто — пишется `case.FCMacro` (скрипт сборки), он тоже в git.
   Тогда `.FCStd` не нужен вовсе: постановка восстанавливается из скрипта и `.inp`.
4. `.frd` (результат) в git не кладётся; при необходимости конвертируется
   (`ccx2paraview`, `cgx`) или пересчитывается — он детерминирован.
5. В отчёте: команда запуска, версия `ccx` (`ccx -v` / вывод баннера), число элементов.

Это то же правило, что для `main.py`: результат должен восстанавливаться прогоном, а не
храниться картинкой.

## 6. Как это встроить в наш процесс

### 6.1 Место в репозитории

```
fea/
  PTK-032-R7X20-22M5P2-00AD4E/
    R1-ring-stiffness/    report.md  job.inp  case.FCMacro  vmises.png
    R2-wall-203-194/      report.md  job.inp  ...
    R3-sep-band-hb/       report.md  job.inp  ...
    R4-teeth/             report.md  job.inp  ...
    R5-pack/              report.md  job.inp  ...
```

Имя папки постановки = `Р-N` из ТЗ (`R1`…`R5`) + короткий смысл. ID — как в `out/`, чтобы
расчёт нельзя было оторвать от конфигурации.

### 6.2 Связь с реестрами

- Пункт `CP-138` — зонтик; каждая постановка закрывает конкретный `OQ` и указана в
  `specs/CODE_PLAN.md`.
- Числа из отчёта попадают в код **только патчем модели** (новое значение в `limits`), после
  чего обязателен прогон `main.py` и регенерация `SPEC-10`. Руками в SPEC-10 не вписываются.
- Закрытие `OQ` — отдельная запись `Д-###` со ссылкой на отчёт: «МКЭ, Р-3, `fea/…/report.md`,
  такой-то предел». Без записи в DECISIONS расчёт не существует для процесса.

### 6.3 Правило устаревания (главное)

Расчёт привязан к геометрии. В отчёте фиксируются **ID конфигурации и sha коммита**, на
которых он выполнен. Дальше действует правило:

> Изменилась геометрия или материал детали — расчёт помечается «устарел» в первой строке
> отчёта, и его число не используется в решениях, пока не пересчитан.

Это не бюрократия. В репозитории уже есть пример обратного: `specs/ptk_designs.yaml` собран
под `…-CFF527` с другим подшипником, шаг 2 не перепрогонялся — и таблица месяцами показывала
конфигурацию, которой в текущем коде нет. С МКЭ будет то же, если не привязывать расчёт к
коммиту: цифра живёт в решении, а геометрия уже другая.

### 6.4 Разделение ответственности

| Роль | Что делает | Что не делает |
|---|---|---|
| Исполнитель расчёта | строит постановку по ТЗ, гоняет сетки, пишет `report.md` с таблицей проверок | не правит `limits` и SPEC-10 |
| Заказчик | проверяет §4 ТЗ (равновесие, сходимость, сверка, единицы), принимает или возвращает | не пересчитывает сам |
| Модель (я) | переводит принятый результат в патч `limits`, перепрогоняет `calc`, регистрирует `Д-###` | не «додумывает» числа, если расчёт не сдан |

### 6.5 Минимальный старт

1. `ccx` + `gmsh` + тест-балка — 15 минут.
2. Р-1 на секторе 90°, две сетки — первый полезный результат (`k_w`), 1–2 дня.
3. По результату Р-1 видно, нужна ли полная модель: если податливость стыка даёт больше
   половины угла — считать стык точнее (Р-4), а не дробить сетку.

## 7. Чек-лист перед сдачей расчёта

- [ ] `ccx` и `gmsh` отвечают в терминале, тест-балка считается
- [ ] единицы: мм, Н, МПа, плотность 7.85e-9 т/мм³, момент в Н·мм
- [ ] материал из `materials.yaml`, источник указан (для ШХ15СГ — пометка OQ-36)
- [ ] сетка: ≥ 4 элемента по толщине стенки, C3D10, число элементов записано
- [ ] два прогона по сетке, изменение σ < 5 %
- [ ] сумма реакций = нагрузке (≤ 0.1 %)
- [ ] сверка с аналитикой (§4 ТЗ), расхождение объяснено
- [ ] съём по путям и сечениям, а не «максимум по модели»
- [ ] `report.md` + `job.inp` + (`case.FCMacro`) в `fea/<ID>/<постановка>/`
- [ ] в отчёте — ID конфигурации и sha геометрии
- [ ] вывод сформулирован как «что меняется в `limits`», а не «напряжения такие-то»
