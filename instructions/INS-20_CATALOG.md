## Зачем свой каталожный номер

У HIWIN каретка и рельс заказываются отдельными кодами, а у неразъёмного
исполнения (matched set) они поставляются только комплектом. Кроме того, не
всякая комбинация существует: например, натяга ZB нет для HG15.

Номер EGC — это одно имя для **проверенной совместимой пары**. Спецификация
станка ссылается на один номер, и код по нему находит обе детали, их размеры,
грузоподъёмность и цену. Если номера нет в `catalog_hiwin_hg_pairs.json`,
такой комбинации не существует, и проверка это сообщит. Длина рельса в номер
не входит: она задаётся в спецификации оси, а раскладку отверстий проверяет код.

## Как читать номер (Д-10)

```
EGC - HG - H 20 C A - P - ZA [-T]
 │     │   │ │  │ │   │   │    └ рельс HGR..T — крепится снизу; нет суффикса — HGR..R, сверху
 │     │   │ │  │ │   │   └ натяг: Z0 лёгкий, ZA средний, ZB тяжёлый
 │     │   │ │  │ │   └ класс точности: C нормальный, H высокий, P прецизионный,
 │     │   │ │  │ │                     SP супер-, UP ультрапрецизионный
 │     │   │ │  │ └ крепление каретки: A сверху, B снизу, C сверху или снизу
 │     │   │ │  └ нагрузка (длина каретки): C тяжёлая, H сверхтяжёлая (удлинённая)
 │     │   │ └ типоразмер: 15, 20, 25, 30, 35, 45, 55, 65
 │     │   └ тип каретки: H квадратная, L квадратная низкая, W фланцевая
 │     └ серия HIWIN HG
 └ наша покупная позиция (EG-machines Component)
```

Пример: `EGC-HG-H20CA-P-ZA` — каретка HGH20CA, прецизионная P, средний натяг ZA,
на рельсе HGR20R. В заказе HIWIN это каретка **HGH20CAZAP** + рельс **HGR20R**
нужной длины. Порядок кода HIWIN — натяг, затем класс; в EGC — класс, затем
натяг, чтобы номера одного класса стояли рядом при сортировке.

Буквы A/B/C крепления меняются только у фланцевых W. Квадратные H и L бывают
только A.

## Символы размеров (как в каталоге)

| Символ | Смысл |
|---|---|
| H | высота узла от основания рельса до верха каретки |
| H1 | зазор под кареткой |
| W, B, C | ширина каретки; расстояния между её крепёжными отверстиями поперёк/вдоль |
| L, L1 | длина каретки полная / корпуса без уплотнений |
| WR, HR | ширина / высота рельса |
| P | шаг крепёжных отверстий рельса |
| E (Es) | расстояние от последнего отверстия до торца рельса |
| C / C0 | динамическая / статическая грузоподъёмность, кН |
| MR, MP, MY | допустимые статические моменты крена, тангажа, рыскания, кН·м |

Длина рельса: L = (n − 1)·P + 2·E. Код проверяет эту формулу на всех стандартных
длинах каталога и предупреждает, если E > P/2.

## `specs/vendor_prices.json` — заполняет заказчик

| Поле | Смысл |
|---|---|
| ключ | код HIWIN (`HGH20CA`, `HGR20R`), номер EGC или ключ тела (`ROLLER_D5x8`) |
| `unit` | `pcs` — за штуку (каретка, тело), `m` — за метр (рельс) |
| `price` | цена в валюте `currency`; `null` — неизвестна |
| `available` | `true` / `false` / `null` — наличие |
| `lead_days` | срок поставки, дней |
| `supplier`, `date` | поставщик и дата цены |

Если позиции нет в каталогах, в `catalog_report.md` появится предупреждение.
Позиции без цены подсчитываются, отчёт о них появится в CP-03.

## Требования к .md-компиляции каталога (для парсера)

Текущий файл разобран без ошибок: 71 каретка, 16 рельсов, 8 типоразмеров.
Переводить его в другой формат не нужно. Новый каталог компилируется по тем же
правилам:

1. Таблица — обычная markdown-таблица; объединённые ячейки раскрыты, значение
   повторено в каждой строке.
2. Над таблицей стоит заголовок или жирная строка с номером таблицы каталога
   (`**Table 2-1-25 …**`). По номеру парсер понимает смысл таблицы.
3. Первая колонка — ключ строки: `Модель` (полный код, `HGW20CC`) или
   `Типоразмер` (`HG20`).
4. Заголовки колонок — символы каталога (`H`, `WR`, `C0`…), единицы — в заголовке
   таблицы, а не в ячейках.
5. Числа — с точкой; разделитель тысяч допускается (`1,960`); нет данных — `–`.
6. Таблицы, которые парсер не понимает, перечисляются в отчёте в разделе
   «Нераспознанные» и на расчёт не влияют.

Для другого производителя заводится запись CAT-## в `specs/CATALOGS.md` и, при
другой структуре таблиц, отдельный парсер (пункт CP).
