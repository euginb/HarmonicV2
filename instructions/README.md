# INS-00 — Инструкции проекта: реестр, режимы работы с ИИ, глоссарий

Раздел `instructions/` — точка входа во всё, что описывает **как работать** с
репозиторием: инструкции к code-first спецификациям (Д-17), порядок работы
с ИИ в разных режимах и ручная подготовка контекста (Д-25, Д-26). Главный
`README.md` описывает проект, структуру и правила GitHub/коммитов/патчей;
всё остальное о процессе — здесь.

### Правило поддержания реестра (Д-25)

1. Новая инструкция `INS-##` или изменение назначения существующей вносится
   в таблицу п. 1 **в том же патче**, что и сама инструкция; новый раздел
   этого файла — в таблицу «Когда открывать instructions/README.md» главного
   `README.md` (Д-29).
2. Номер инструкции к code-first спецификации совпадает с её номером
   (INS-10 ↔ SPEC-10, Д-17); инструкции по процессу работы — серия `INS-9#`.
3. Главный `README.md` ссылается только на этот файл; списки отдельных
   инструкций в нём не ведутся.
4. При review проверяется: каждый файл `instructions/INS-*.md` есть в
   таблице, каждая строка таблицы указывает на существующий файл.

## 2. Режимы работы с ИИ

Запись в репозиторий в любом режиме — только человек: ИИ выдаёт unified
diff, заказчик проверяет (`tools/fix_diff.py` → `git apply --check`),
применяет, коммитит и пушит (правила — главный `README.md`).

| | A. Super Agent | B. AI Chat + GitHub | C. AI Chat без GitHub |
|---|---|---|---|
| Где | Genspark Super Agent (песочница + AI Drive) | AI Chat Genspark или другая модель с веб-доступом | любая модель без доступа к GitHub |
| Доступ к файлам | зеркало `/HarmonicV2-main.zip`, развёрнутое в песочнице | GitHub REST API и raw (Д-12, Д-15), pinned к base sha | только приложенные файлы |
| Контекст | агент сам: `context_bundle.py` по ключам задачи (Д-20) | модель читает по Д-12/Д-15; стартовый контекст — bundle по ключам, приложенный заказчиком (INS-90) | приложенный bundle: по ключам или полный `AUDIT_BUNDLE.md` (INS-90) |
| Проверки | агент гоняет `main.py`, `fix_diff.py`, `git apply --check` до выдачи | только у заказчика | только у заказчика |
| Выдача патча | файлом в AI Drive `/HarmonicV2-patches/` | текстом в чате | текстом в чате |
| Порядок | `HarmonicV2-workflow.md` (актуальный — AI Drive) | п. 2.2 | п. 2.3 |

### 2.1. Режим A — Super Agent

Работает только в инфраструктуре Genspark при подключённом AI Drive (Д-20).
Задача открывается фразой: «Работаем с HarmonicV2: зеркало
`/HarmonicV2-main.zip`, порядок `/HarmonicV2-workflow.md` в AI Drive, база
<sha>: <задача> (CP-##)». После каждого push — «синхронизируй зеркало
HarmonicV2». Детали — `/HarmonicV2-workflow.md` в AI Drive.

### 2.2. Режим B — AI Chat + GitHub

1. Заказчик называет base sha (`git rev-parse HEAD`) — все чтения pinned к нему.
2. Стартовый контекст: заказчик собирает bundle по ключам задачи
   (`tools/context_bundle.py`, INS-90 §2) и прикладывает к первому сообщению.
   Это экономит токены модели: ~30–110 КБ вместо обхода репозитория.
3. Недостающие файлы модель читает сама по Д-15: raw (до ~10 КБ) →
   `/contents/<путь>?ref=<sha>` по частям → jsDelivr.
4. Модель выдаёт патч текстом по правилам README; первая строка
   `# base: <sha>, CP-##`.

### 2.3. Режим C — AI Chat без GitHub

1. Весь контекст — приложенные файлы: bundle по ключам задачи (предпочтительно)
   или снимок `AUDIT_BUNDLE.md` (review, широкие задачи; объём — профилями
   исключения, INS-90 §3.3).
2. Модель работает только с тем, что приложено, и называет файлы, которых ей
   не хватает; заказчик досылает их (отдельным bundle по путям).
3. Патч — текстом в чате, base sha — из заголовка bundle.

### 2.4. Начало сессии (любой режим)

ИИ читает фиксированный «пол»: `README.md`, `specs/DECISIONS.md`,
`specs/CODE_PLAN.md`, `specs/CANCELLED.md`, `reports/checks.md` — он
автоматически входит в начало любого bundle (`context_bundle.py`); затем —
файлы по ключам задачи и нужные инструкции этого раздела.

## 3. Порядок работы с code-first спецификациями (Д-17)

Code-first спецификация — результат прогона `main.py`, руками она не правится.
Чтобы изменить результат, меняют **входные файлы** и запускают прогон заново.
Инструкция описывает, какие входные файлы есть, что означает каждый параметр
и как читать результат.

| Инструкция | Спецификация / БД | Входные файлы |
|---|---|---|
| [INS-10_PTK_CALC.md](INS-10_PTK_CALC.md) | `specs/SPEC-10_PTK_CALC.md`, `specs/ptk_configs.json` | `specs/ptk_input.json`, `specs/vendor_prices.json` → `bodies` |
| [INS-20_CATALOG.md](INS-20_CATALOG.md) | `specs/catalog_hiwin_hg.json`, `specs/catalog_hiwin_hg_pairs.json`, `reports/catalog_report.md` | `docs/HG-Series-Catalog_opt.md`, `specs/vendor_prices.json` |

1. Правите входной файл (`specs/*_input.json`, `specs/vendor_prices.json`).
2. `python main.py` — результат в `out/specs/` и `out/reports/`.
3. Смотрите `out/reports/checks.md`: «все пройдены» = код выхода 0.
4. Переносите результат: вручную или `python main.py --publish` (Д-14).
5. Коммит.

В JSON ключи, начинающиеся с `_` (`_comment`), — комментарии, код их пропускает.
Неизвестный параметр (опечатка в имени) — ошибка прогона, а не молчаливое игнорирование.

## 4. Глоссарий проекта

| Сокращение | Расшифровка |
|---|---|
| ПТК | волновой редуктор с промежуточными телами качения (ролики/шарики) |
| ГК | волновой редуктор с гибким колесом (классический harmonic drive) |
| ЭЭС | электроэрозионная система, прошивочный электроэрозионный станок |
| ЭХП | электрохимическое полирование — снятие перелитого слоя после ЭЭС (Д-05) |
| HMC / VMC | горизонтальная / вертикальная компоновка станка (`docs/cnc_axes_guide.md`, Д-09) |
| SM / SE | станок фрезерный (milling) / электроэрозионный (erosion) — SPEC-01 |
| K1 / K2 / K3 | классы точности закладных: базовые / силовые / вспомогательные — SPEC-02 |
| M1 … M4 | способы монтажа закладных в литьё — SPEC-02 |
| Д-## | принятое решение (`specs/DECISIONS.md`) |
| OQ-## | открытый вопрос (`specs/DECISIONS.md`) |
| CP-## | пункт плана доработки кода (`specs/CODE_PLAN.md`), в коде — `TODO(CP-##)` |
| X-## | отменённое положение (`specs/CANCELLED.md`) |
| CAT-## | каталог производителя в реестре `specs/CATALOGS.md` |
| EGC | префикс нашего каталожного номера покупной позиции (EG-machines Component, Д-10) |
| SPEC-## / INS-## | спецификация / инструкция к ней |
| base sha | коммит, от которого строится патч и читается контекст (`git rev-parse HEAD`) |
| bundle | один текстовый файл с контекстом для ИИ: по ключам (`context_bundle.py`) или полный снимок (`AUDIT_BUNDLE.md`) — INS-90 |

## 5. Обозначения волнового редуктора ПТК

| Обозначение | Смысл |
|---|---|
| u | передаточное число |
| z | число впадин жёсткого колеса (внешнего венца) |
| n | число тел качения в ряду, n = z − 1 |
| e | эксцентриситет генератора волн |
| Ø дел. | делительный диаметр — окружность центров тел |
| венец | внешнее жёсткое колесо с профилем впадин; неподвижно, крепится к корпусу/машине |
| сепаратор | кольцо с гнёздами тел; выходное звено |
| генератор волн | эксцентрик (кулачок) с подшипником; входное звено |
| ряд | один слой тел по оси; рядов 4, фазы 0/90/180/270° (Д-08) |
