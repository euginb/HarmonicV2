# INS-10 — ПТК: расчёт и проработка, шаги 1–2

Связанные решения: Д-08, Д-11, Д-16, Д-18, Д-19, Д-22, Д-31, Д-33, Д-35, Д-37, Д-38,
Д-40…Д-43, Д-45, Д-46, Д-48, Д-51, **Д-60** (формат конфигурации и явные шаги).
Код: `egm/ptk.py` (подбор, ID), `egm/ptk_profile.py` (профиль, траектория (6) Янгулова),
`egm/ptk_force.py` (силы, Герц, момент), `egm/ptk_parts.py` (сепаратор, эксцентрик шага 1),
`egm/ptk_design.py` (шаг 2), `egm/ptk_layout.py` (конструктив). Спецификация —
`specs/SPEC-10_PTK_CALC.md` (шаг 1), `specs/SPEC-11_PTK_DESIGN.md` (шаг 2).

## 1. Что это и для чего

Функционал ПТК подбирает и проверяет исполнения одноступенчатого волнового редуктора
с промежуточными телами качения: для каждого u из диапазона, каждого тела качения,
каждого типа генератора и каждого крепления венца считается геометрия, профиль венца,
допускаемый выходной момент M и проверка габарита D. Результат — таблица SPEC-10, где
каждое исполнение имеет ID (Д-22). Затем выбранное исполнение прорабатывается: вал,
соединение эксцентрик–вал, балансировка под имеющиеся свёрла, опоры выхода. По выбранному
строится комплект чертежей — это уже **INS-30**.

Состав функционала: код — `egm/`; конфигурация — ручные YAML-файлы в `specs/`
(описание каждого параметра — комментарием рядом с ним, Д-60); инструкции — этот файл
и INS-30. Результаты прогона (SPEC-10/SPEC-11, `ptk_configs.json`, `ptk_designs.json`)
машина пишет сама — руками их не править (code-first).

## 2. Правила и flow

| Этап | Команда | Вход | Выход |
|---|---|---|---|
| 1. Расчёт | `python main.py calc --publish` | `specs/ptk_input.yaml`, `specs/vendor_prices.yaml` | `specs/SPEC-10_PTK_CALC.md`, `specs/ptk_configs.json` |
| — выбор | **человек**: по SPEC-10 выбрать исполнение (ID) | SPEC-10 | исполнение для шага 2 |
| 2. Проработка | `python main.py design --publish` | **опубликованный** `specs/ptk_configs.json` (выход шага 1), `specs/ptk_design_input.yaml` | `specs/SPEC-11_PTK_DESIGN.md`, `specs/ptk_designs.json` |
| 3. Чертежи | `python -m egm.cad --spec specs/cad_set.yaml` | `specs/cad_set.yaml` + `ptk_configs.json` + `ptk_designs.json` | `out/cad/**.svg|.step` |

Связь шагов явная (Д-60): вход шага 2 — опубликованный результат шага 1
`specs/ptk_configs.json`. Шаг 2 гоняется отдельно, не пересчитывая шаг 1: прогнали шаг 1,
выбрали исполнение, вписали проработку в `designs[]`, прогнали шаг 2 — сколько угодно раз.
`python main.py` без аргументов — прежний полный прогон: проверки ПО, шаг 1, шаг 2 по его
же свежим исполнениям, проверка номенклатуры, каталог (INS-20).

Почему у шага 2 «вход из будущего»: `designs[].id` ссылается на результат шага 1, хотя
файл заполняется до его прогона — это нормально, порядок такой: шаг 1 → выбор → шаг 2.
Чтобы проработка не терялась при смене хэша шага 1 (правка параметров меняет ID),
`id` пишут **префиксом без хэша** (Д-51, пример — в `ptk_design_input.yaml`); уточнение
нескольких исполнений под одним префиксом — полями `bearing` / `gen`.

Порядок изменения результатов — code-first: правите ручной конфиг (`specs/*.yaml`) →
прогон → смотрите `out/reports/checks.md` («все пройдены» = код выхода 0) → переносите
`--publish` → коммит. Значения и их смысл — в комментариях конфигов (первоисточник, Д-60);
этот файл — про логику и следствия.

## 3. Шаг 1 — «Расчёт» (`python main.py calc`)

### Вход

`specs/ptk_input.yaml` — `limits` (геометрия, материалы, диапазон), набор креплений
`ring_mounts`, режим `mount_mode`, таблица `fasteners`; `specs/vendor_prices.yaml` —
тела качения `rollers`, подшипники генератора `bearings`, цены `items`.
`pins` — штифты ГОСТ 24296 (Ø, стандартные длины); цена — items P<d>x<l> (Д-74)

Значения и «как влияет» — комментариями в самих файлах; ниже — только то, что нужно
для чтения результата.

### Что происходит

Для каждой тройки (u, тело, генератор) строится одноступенчатый редуктор; расчёт идёт
от центра наружу (обозначения — колонки SPEC-10):

```
z = u + 1,  n = u                          Д-31, Д-38: венец неподвижен, выход — сепаратор
aω    = a_k · Dш  (или a_w тела)           эксцентриситет генератора
RΣ min — наибольшее из условий             подрез, сепаратор, вал; колонка R_by (Д-38)
Dг    = D подшипника (bearing, Д-40) | Ø эксцентрика (eccentric, Д-42)
RΣ    = (Dг + Dш)/2                        окружность центров тел генератора
DВ    = 2(RΣ + aω) + Dш                    диаметр впадин венца
Dверш = 2(RΣ − aω) + Dш                    диаметр вершин
Dотв  = DВ + 2c     вверх до d_bc_step     окружность центров отверстий (Д-35)
D     = Dотв + 2c   вверх до d_out_step    наружный диаметр, ≤ d_out_max (Д-43)
c     = max(wall_min + d_clear/2, dk/2 + head_margin)
M     = min(M_H, M_B, M крепл./safety)     Д-41; в скобках в SPEC-10 — ограничитель
```

c — расстояние от впадин до оси отверстия и от оси до наружной кромки; зависит только
от болта: чем крупнее болт, тем больше D при тех же телах. Какие строки попадают в
таблицу при нескольких креплениях — `mount_mode` (справочник §6.2). Пар «тело +
генератор», исключённых по технологии, касается §6.5 (Т1–Т4).

### Выход

`specs/ptk_configs.json` — все исполнения машиночитаемо (вход шага 2 и INS-30);
`specs/SPEC-10_PTK_CALC.md` — та же таблица с расшифровкой. Оба — code-first.

### Как читать SPEC-10

Сначала «Статус». «нет» — причина в разделе «Нереализуемые конфигурации» (и в списке
ошибок в конце); коды Т# — §6.5; исключённые (Т1) — отдельным списком. «Dш max» — какое
тело поместилось бы при данном u. «M» — допускаемый выходной момент, в скобках — что его
ограничивает: «контакт» — Герц (M_H), «подшипник» — C0 подшипника генератора (M_B),
«крепление» — M крепл./safety.

Типовые правки (значения — в `ptk_input.yaml` / `vendor_prices.yaml`):

| Нужно | Что менять |
|---|---|
| проверить болт M5 вместо M4 | запись `"M5x8P2"` в `ring_mounts`, первой — чтобы стала основной |
| 12 отверстий вместо 8 | запись с `"n": 12` в `ring_mounts` |
| видеть все крепления, а не первое прошедшее | `mount_mode: all` |
| M ограничивает «крепление» | больше болтов или крупнее болт; `mu`, `safety` — по данным испытаний |
| M ограничивает «подшипник» | подшипник с большим C0 в `bearings` или тело крупнее |
| глубже волна, больше α max | больше `limits.a_k` (растёт RΣ по подрезу и D) |
| считать только с подшипником | `limits.gen_types: [bearing]` |
| добавить ролик Ø3×5 | запись в `vendor_prices.yaml` → `rollers` и `items` |
| таблица только для u = 30…60 | `limits.u_list: [30, 40, 50, 60]` |

## 4. Шаг 2 — «Проработка» (`python main.py design`)

### Вход

**Опубликованный результат шага 1** — `specs/ptk_configs.json` (связь шагов, §2) —
ID шага 1 не меняются; и `specs/ptk_design_input.yaml` — проработки `designs[]`:
имя (`name`), уточнение выбора (`bearing`, `gen`), вал (`shaft.d`, `bore`, `link`,
допускаемые), балансировка (`balance.drills` — Ø только из имеющихся свёрл), конструктив
(`layout`, Д-55) и опоры (`supports`). Значения и «как влияет» — комментариями в файле.
Порядок работы и причина «входа из будущего» — §2.

### Что считает

```
T_вх = M/(u·eta),   T_э = ecc_share·T_вх      M — допускаемый выходной момент SPEC-10
d_t  = d − t1 (шпонка),   β = bore/d_t
τ    = 16·T_вх/(π·d_t³·(1 − β⁴)) ≤ [τ]         d_req — Ø, при котором τ = [τ]
σ_см = 2·T_э/(d·(h − t1)·l_p) ≤ [σ см]        l_p = t − b, t — толщина эксцентрика
стенка у паза и напротив эксцентриситета (Dэ/2 − aω − d/2) ≥ ecc_wall_min
```

Шпонка — первая строка `keys.table` с d ≤ `d_max` (призматическая исп. A, DIN 6885 /
ГОСТ 23360; сверить со справочником). Балансировка — как на шаге 1 (Д-36, Д-46), но
диаметры только из `balance.drills`. Масса пакета: эксцентрики, подшипники, вал длиной
B пакета; тела не учитываются. J вх — на входном валу (подшипники — кольца, обегающие
ось на aω, оценка сверху), J вых = J вх·u². Вал, шпонка и балансировка шага 2
переопределяют предварительные оценки шага 1 (Д-48, Д-53).

### Выход

`specs/ptk_designs.json` — проработки машиночитаемо (вход INS-30, в том числе для
`--design`); `specs/SPEC-11_PTK_DESIGN.md` — таблицы проработок, конструктива и оснастки.

### Как читать SPEC-11

«Статус» «нет» — причина в списке ошибок SPEC-11 (например, «вал Ø8: τ = 43.7 > [τ] = 25 МПа —
нужен d ≥ … мм»). «T вх / T э» — момент вала и доля одного эксцентрика. «Остаток» —
дисбаланс после отверстий, г·мм: «−» — перекомпенсация; больше 5 % U — предупреждение.
Детали проработки — таблица `<ID>.03<вар>-<name>` с углом паза и рядами.

Типовые правки:

| Нужно | Что менять |
|---|---|
| вал не проходит по τ | `shaft.d` ≥ d_req из текста ошибки (шпонка сменится по `keys.table`) |
| τ близко к [τ] | следующий Ø вала новой записью `designs[]`: запас нужен при росте M (крепление, OQ-08) |
| полый вал под кабели | `shaft.bore`; проверить τ и `shaft.wall_min` |
| большой остаток балансировки | расширить `balance.drills` или `balance.n_max` |
| сравнить варианты вала | несколько записей с одним `id` и разными `name` |
| проработка потерялась после смены хэша | `id` — префиксом без хэша + `bearing` / `gen` (Д-51) |

## 5. Дальше — комплект чертежей

Спецификация комплекта — `specs/cad_set.yaml`, запуск `python -m egm.cad --spec`:
запись — исполнение целиком (id, `design` — проработка шага 2, `assy` — сборка,
фильтры `rows`/`parts`). Детали и сборки: `python -m egm.cad <ID>.03B-K10 --row 2`,
`python -m egm.cad <ID> --design K10 --assy`. С проработкой Ø отверстия эксцентриков,

без неё — предварительные шага 1 (`limits.shaft_d_min`). Всё — INS-30.

## 6. Справочник

### 6.1 Обозначения

u — передаточное число; z — число впадин венца, z = u + 1 (Д-31); n — число тел в ряду;
aω — эксцентриситет генератора; RΣ — окружность центров тел; DВ / Dверш — впадины /
вершины венца; Dотв — окружность центров отверстий; D — наружный диаметр венца;
s — сдвиг сверловки ряда. Полный словарь — instructions/README.md §5.

### 6.2 Крепления венца: mount_mode и приоритет (Д-16, Д-33)

`ring_mounts` — словарь «имя → крепление»; каждая тройка (u, тело, генератор) считается
со всеми записями в порядке словаря. Режим `mount_mode`: `first_ok` (по умолчанию) —
в таблицу попадает первое прошедшее все проверки крепление (если ни одно — первое по
списку, с его ошибками); `all` — все, по строке на каждое. Порядок записей — приоритет:
первым основное (крупнее болт, больше M крепл.), за ним запасные для тесных случаев.
Имя (`M4x8P2`) — только метка: в ID не входит, состав отверстий входит (`8M4P2`).
Без штифтов (`pins: 0`) угловую фазу ряда держать нечем — только для проверки.

Шаг (хорда) = Dотв·sin(180°/n) ≥ max(dk + web_min, d_clear + wall_min);
M крепл. = n·F_M·mu·Dотв/2 — момент, передаваемый трением стыка (штифты не учитываются).
Одни и те же отверстия крепят редуктор в машине и базируют венец на оснастке станков
(ЭЭС, фрезерование); штифты H7 задают угловое положение.

### 6.3 Профиль венца (Д-38)

Вывод формул — SPEC-10 (текст генерируют `egm/ptk_profile.py`, `egm/ptk_force.py`).
Следствия для выбора параметров:

1. Профиль — эквидистанта траектории центра тела (6) Янгулова на Dш/2; глубина волны
   DВ − Dверш = 4aω — задаётся `a_k` и не зависит от u.
2. Угол передачи α max ≈ arctg √(2aω/Dш): при `a_k` = 0.2 около 32°. Меньший угол —
   больше радиальная сила на тело при том же M.
3. При больших u RΣ ограничивает подрез (`r_tip_min`): кривизна траектории на вершине
   растёт как aω·z², RΣ и D растут почти пропорционально u — u = 80, 100 выходят
   за `d_out_max`.
4. При малых u RΣ задают сепаратор (`sep_web_min`), вал или подшипник генератора;
   колонка «RΣ задан» показывает, какое условие сработало.

### 6.4 Фазировка рядов и сдвиг сверловки (Д-19)

Ряд k — копия ряда 1, повёрнутая на φk (эксцентрик генератора). Отверстия пакета
сквозные, в корпусе они на одних и тех же углах — поворот переносится на сверловку:

```
p = 360/z                 шаг впадин
N                         порядок симметрии сверловки (болты + штифты)
g = 360 / НОК(z, N)       шаг, по модулю которого сдвиги неразличимы
s_k = (−φk) mod g         поворот сверловки ряда k от впадины 0, град
s_k·π·Dотв/360            то же по дуге, мм (ptk_configs.json → s_arc_mm)
cage_k = ((−s_k·z − φk)/n) mod (360/n)   поворот окон ряда k в сепараторе (Д-46)
```

Венцы с одинаковым s — одна деталь. Буквы вариантов — `.01A`, `.01B`… — группы равного
s по порядку рядов: первая группа — A, следующая новая — B; ряды варианта —
`ptk_configs.json → parts[].rows` (таблица «Варианты деталей» — INS-30 §5). Все 4 венца
одинаковы, если z кратно 4 или N кратно 4. Примеры для 8 болтов:

| Штифты | N | Венцов при z = 20 | при z = 63 |
|---|---|---|---|
| 0 | 8 | 1 | 1 |
| 2 (напротив) | 2 | 1 | 2 |
| 4 (через 90°) | 4 | 1 | 1 |
| 1 или 3 | 1 | 1 | 4 |

Несимметричные штифты исключают неверную установку венца, но увеличивают число
вариантов и управляющих программ. Допущение: фаза — угол поворота эксцентрика ряда;
если фаза задаётся иначе (общий эксцентрик, поворот профиля на долю шага), формула
другая — сообщить исполнителю.

### 6.5 Технологические коды Т1–Т4 (Д-42, Д-45)

| Код | Когда | Что значит для пользователя |
|---|---|---|
| Т1 | шарик + `bearing` | исполнение исключено: на кольце покупного подшипника жёлоб не сделать; строка — в разделе «Исключённые по технологии» SPEC-10 |
| Т2 | шарик + `eccentric` | контакт с эксцентриком считается по жёлобу `groove_f`; жёлоб — на чертёж .03 |
| Т3 | шарик + `eccentric` | в венце жёлоба нет, обычно эта пара ограничивает M (B_D3, u = 10: ≈ 1 Н·м); жёлоб в венце — OQ-11 |
| Т4 | любое тело + `eccentric` | скольжение тело/эксцентрик ≈ ω·Dг/2; предел скорости входа не проверяется (OQ-10) |

Коды стоят в колонке «Статус» («OK (Т4)»); полная расшифровка — в конце SPEC-10.
Ролик с `bearing` кодов не получает.

### 6.6 ID исполнения и деталей (Д-22)

По ID генерируются чертежи (INS-30), он же стоит на чертеже и детали.

```
PTK-063-R2X4_2-8M3P2-BE3303
│   │   │      │     └ хэш (6 hex) параметров геометрии
│   │   │      └ отверстия венца: 8×M3 + 2 штифта (без штифтов — 8M3)
│   │   └ тело: R<Ø>X<L> — ролик, B<Ø> — шарик; дробь через «_»: 4_2
│   └ u, 3 цифры
└ тип редуктора (SPEC-01)
```

Хэш — от снимка геометрии (`ptk_configs.json → geom`): `GEOM_REV`, u, тело, параметры
`limits` (перечень в `egm/ptk.py`), крепление, `fasteners.<bolt>.d_clear, dk`,
подшипник и тип генератора. Правка любого из них даёт новый ID; `mu`, `safety`, `F_M`,
`web_min`, `u_list`, материалы, `sigma_H_*`, `groove_f`, имя крепления и `mount_mode`
ID не меняют; `4` и `4.0` равнозначны. Смена формул геометрии повышает `GEOM_REV` —
меняются все ID (сейчас GEOM_REV = 6). Найти запись по ID — `ptk.find(rows, id)`;
ID детали — `<ID>.<NN>[вариант]`:

| NN | Деталь | Статус |
|---|---|---|
| 01A, 01B… | венец — группы равного сдвига сверловки s по порядку рядов (§6.4): одинаковые буквы — одна сверловка и одна УП; ряды варианта — `parts[].rows` | генерируется |
| 02, 02A/02B/02C | сепаратор, буква по конструктиву (Д-73): A — стакан монолитом (L1), B — обечайка с буртом (L2), C — обечайка без бурта (L3); без проработки — одна деталь без буквы | генерируется |
