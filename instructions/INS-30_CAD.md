# INS-30 — Чертежи ПТК: комплект по спецификации и по ID

Связанные решения: Д-22 (ID исполнения), Д-24 (номенклатура), Д-30 (2D и 3D из одной
геометрии), **Д-61** (спецификация комплекта). Код — `egm/cad/`; данные —
опубликованные `specs/ptk_configs.json` (code-first, результат шага 1) и
`specs/ptk_designs.json` (шаг 2), номенклатура — `specs/products.yaml` (spec-first,
SPEC-03), комплект — `specs/cad_set.yaml` (Д-60, Д-61); конфигурация механизма
(пути, форматы 3D-экспорта) — общий конфиг `configs/application.yaml` (Д-64, §7).

## 1. Что это и для чего

Генератор строит 2D-чертежи (SVG, масштаб 1:1, мм — браузер, Inkscape) и 3D-модели
(STEP, ISO 10303 — FreeCAD, КОМПАС-3D, SolidWorks) из одной геометрии (Д-30) по ID
исполнений калькулятора ПТК. Двумя путями:

* **Комплект по спецификации** (основной, Д-61): файл `specs/cad_set.yaml` перечисляет
  исполнения целиком — что строить, с какой проработкой, с сборкой или без;
  генератор сам строит все детали с генераторами плюс сборку. Комплект = один заказ,
  воспроизводится одним файлом.
* **По ID** (низкоуровневый): одна команда — одна позиция; для точечных прогонов
  и проверки одной детали.

## 2. Правила и flow

Место в цепочке (INS-10 §2): после шага 1 («Расчёт») и шага 2 («Проработка»).
Генератор читает **опубликованные** `specs/ptk_configs.json` и `specs/ptk_designs.json` —
они должны соответствовать текущему коду и конфигам: сначала
`python main.py --publish` с кодом выхода 0. Конфигурация механизма —
`configs/application.yaml` (Д-64, §7); ручной конфиг комплекта —
`specs/cad_set.yaml` (Д-61, §3), номенклатура — `specs/products.yaml`;
выход в `out/cad/` в git не хранится — чертёж воспроизводится командой по ID.

Для STEP нужен CadQuery: `pip install cadquery`. Без него строятся только SVG,
в выводе «step: пропущен». Для `.FCStd` — установленный FreeCAD (§7); без него
«freecad: пропущен».

## 3. Спецификация комплекта — `specs/cad_set.yaml` (Д-61)

Запуск: `python -m egm.cad --spec specs/cad_set.yaml`. Каждая запись `items[]` —
исполнение ЦЕЛИКОМ: строятся все его детали, у которых есть генератор
(`products.yaml → cad`), затем опционально сборка.

| Поле записи | Значение | По умолчанию |
|---|---|---|
| `id` | исполнение или ID детали из SPEC-10 / `ptk_configs.json`; префикс без хэша допустим (Д-51) — резолвится по configs | обязателен |
| `design` | имя проработки шага 2 (`designs[]` в `ptk_design_input.yaml`, SPEC-11): эксцентрики и вал — по проработке, сборка `<ID>-<name>.step` | без — предварительный эксцентрик шага 1 |
| `assy` | `true` — дополнительно сборка исполнения одним STEP (Д-49) | false |
| `rows` | `all` или список рядов `[1, 2, 3, 4]` — детали только этих рядов | `all` |
| `parts` | `all` или список позиций `["01", "05"]` — только они | `all` |

Уровень файла: `step: spline | poly | off` — контур впадин в STEP (§6),
ко всем записям. Готовый рабочий пример — в самом файле `specs/cad_set.yaml`.

## 4. Низкоуровневый запуск по ID

| Команда | Что строится |
|---|---|
| `python -m egm.cad <ID исполнения>` | все детали исполнения, у которых есть генератор |
| `python -m egm.cad <ID детали>` | одна деталь, например `PTK-020-R5X8-8M4P2-00124C.01A` |
| `python -m egm.cad <ID1> <ID2> …` | несколько аргументов по очереди |
| `python -m egm.cad <ID> --phase 90` | венец ряда с фазой φ = 90° (`row_phases`), на чертеже — направление его эксцентрика; файл `<NN><вар>-r<k>.svg` |
| `python -m egm.cad <ID> --row 2` | то же по номеру ряда |
| `python -m egm.cad <ID> --assy`              | сборка исполнения одним STEP `<ID>.step`: дерево ROWk (phi = …) → детали и BODIES_ROWk, слои 01_RING…REF, цвета, атрибуты CAx-IF; дубль дерева, метаданных и предлагаемые виды — `<ID>.assy.json` (Д-49, Д-50, OQ-14); имена узлов — только латиница (Д-52); метаданные во FreeCAD — макрос tools/freecad_meta.py; чертежи деталей во FreeCAD TechDraw — макрос tools/freecad_techdraw.py: геометрия и размеры по 3D из STEP, эталоны и легенда — `.assy.json → drawings`, расхождения — предупреждения на листе и в `<ID>.techdraw.md` (Д-65, OQ-20) |
| `python -m egm.cad <ID>.03B-K10 --row 2` | эксцентрик проработки K10 шага 2 (`specs/ptk_designs.json`, Д-48): Ø вала, паз, балансировка — по SPEC-11; файл `03B-K10-r2.svg` |
| `python -m egm.cad <ID> --design K10 --assy` | сборка с эксцентриками и валом проработки: `<ID>-K10.step`, `<ID>-K10.assy.json`; с конструктивом строятся `.02A\|B-<name>`, `.07A\|.07B-<name>`, `.11-<name>`; в сборке — `.09`, `.10` (×2), удлинённый вал (CP-45); без `--design` — предварительный эксцентрик шага 1 (вал `limits.shaft_d_min`) |

ID исполнения — колонка ID в SPEC-10 или `ptk_configs.json → id`; ID деталей,
их сдвиги s и ряды — `ptk_configs.json → parts[]`. В команде с `--design` указывайте
ID с текущим хэшем (как в SPEC-10) — `ptk_designs.json` хранит полные ID; префикс без
хэша здесь не резолвится (в `--spec` — резолвится, §3).
Коды выхода: 0 — построено; 1 — ID не найден, нет генератора или ошибка
геометрии; 2 — нет аргументов.

## 5. Результат

`out/cad/<ID исполнения>/<NN><вариант>.svg` и `.step` (+ `.FCStd` при включённом
альтернативном экспорте — §7).

Вывод консоли дублируется в `reports/cad_report.md` (Д-14; переписывается каждым
запуском, в конце лога печатается, куда сохранён): пути — от корня репозитория,
перед каждой позицией в отчёте — легенда: что это за чертёж (SVG — 2D-вид по оси,
STEP — 3D-модель, генератор) и что это за деталь (позиция, название, вариант, ряды
пакета, проработка). Фатальный traceback идёт только в stderr — в отчёт не попадает.

Венец `.01`: наружный контур, контур впадин (дуги, Д-30), окружность центров
гнёзд и окружность отверстий (штрихпунктир), крепёжные отверстия и штифты H7
со сдвигом s; размеры Øнар, Ø окр. отв., Ø впадин, Ø центров гнёзд; в шапке —
ID, крепёж, z, s, толщина, ряды пакета, в которых стоит этот вариант.

Буква варианта в ID и в легенде — по типу вариантности позиции (`products.yaml →
variant`, перечень — SPEC-03, расшифровка — Д-63). Что различает варианты:

| Позиция | Вариантность | Что различает буквы |
|---|---|---|
| `.01` венец | `ring_phase` | группы равного сдвига сверловки s по порядку рядов (Д-19, §6.4 INS-10): A — первая группа, B — следующая; «ряды пакета» в легенде — в каких рядах стоит этот вариант |
| `.02` сепаратор | `layout` | конструктив (Д-54, Д-55): A — стакан (дно + ступица, L1), B — обечайка (L2); без проработки буквы нет |
| `.03` эксцентрик | `row` | ряд k: паз шпонки и отверстия балансировки на угле `key_angle` − φk (Д-46); A — ряд 1, B — ряд 2 … |
| `.05` шайба | `thick` | толщина h (Д-53): A — у торцов пакета (h = row_gap + (шаг − l)/2), B — между рядами (h = row_gap + шаг − l) |
| `.07` крышка | `side` | сторона (Д-54): A — вход, B — выход |
| `.04`, `.06`, `.08`… | `none` | без вариантов — одна деталь на исполнение |

Буква — только метка: одинаковые буквы — одинаковые детали (одна УП, один номер);
расчёт букв — INS-10 §6.6, `ptk_configs.json → parts[]`.

«предупреждение: … нереализуема: …» — конфигурация не прошла проверки SPEC-10
(причина в тексте), чертёж строится только для анализа. ID не найден —
изменилась геометрия (новый хэш, Д-22), новый ID — в SPEC-10.

## 6. Контур впадин в STEP (CP-29)

Профиль — эквидистанта траектории центра тела по (6) Янгулова (Д-38), 24 точки на шаг
впадин (`ptk_profile.profile_points`, k = 24); в SVG — ломаная по этим точкам. В STEP
деталь строится одной гранью и одним выдавливанием, без булевых операций. Контур
впадин: `--step spline` (по умолчанию) — периодический B-сплайн через точки профиля,
одна гладкая боковая грань; `--step poly` — ломаная, z·k плоских граней (если сплайн
не строится или невалиден); `--step off` — без STEP, только SVG. Приоритет:
флаг `--step` → уровень файла комплекта `step:` (§3) → `cad.export.step.mode`
из `configs/application.yaml` (§7, Д-64).

## 7. Конфигурация — `configs/application.yaml` (Д-64)

Общий конфиг приложения (YAML, Д-60): пути (`paths:`), ссылки на пучок текущих
конфигов (`configs:` — сами конфиги НЕ вкладываются, правятся по своим путям),
разделы продуктов (`products:` — по продукту из реестра `configs.products` =
`products.yaml`; входы шагов 1–2 — `products.PTK.configs.input / design_input`),
механизм чертежей (`cad:`). Код берёт данные из него, а не из хардкодов:
`egm/config.py → load_app / cfg_file`; разделы продуктов проверяет полный прогон
(`egm/products.py → check_app`): раздел есть в реестре, `enabled` — при непустой
номенклатуре.

Механизм чертежей (`cad:`):

| Параметр | По умолчанию | Значение |
|---|---|---|
| `cad.out_dir` | `out/cad` | каталог вывода чертежей |
| `cad.report` | `reports/cad_report.md` | отчёт прогона (Д-14, Д-62) |
| `cad.svg.enabled` | `true` | 2D-вид по оси (1:1, мм) |
| `cad.export.step.enabled` | `true` | основной 3D-экспорт — STEP (Д-32, CP-29) |
| `cad.export.step.mode` | `spline` | контур впадин (§6): `spline` \| `poly` |
| `cad.export.freecad.enabled` | `false` | альтернативный 3D-экспорт — FreeCAD, `.FCStd` |
| `cad.export.freecad.command` | `FreeCADCmd` | головной FreeCAD: `freecadcmd` / `FreeCADCmd` / полный путь |

Два формата 3D-экспорта из одной геометрии (Д-30, Д-32): STEP — основной; FCStd —
из STEP же: головной FreeCAD (команда выше) импортирует его скриптом-конвертером
(`egm/cad/freecad.py`, пишется в каталог вывода) и сохраняет документ рядом —
`out/cad/<ID>/<деталь>.FCStd`, сборка `<ID>[-<name>].FCStd`. Без FreeCAD (команда
не найдена) или без CadQuery — «freecad: пропущен», прогон не падает.
Метаданные сборки во FreeCAD — макрос tools/freecad_meta.py (Д-50).

## 8. Номенклатура и состав по умолчанию

Номенклатура — `specs/products.yaml → PTK.parts.<NN>`, поля — SPEC-03. Две позиции
ПТК приняты по умолчанию; меняется правкой YAML и прогоном `python main.py`:

| Позиция | По умолчанию | Альтернатива — что вписать |
|---|---|---|
| `PTK.parts."02"` сепаратор | одна деталь на пакет: `"variant": "none", "qty": 1` | по ряду: `"variant": "row", "qty": "rows"` (детали `.02A…D`) |
| `PTK.parts."03"` генератор | эксцентрик на ряд: `"variant": "row", "qty": "rows"` | единый вал: `"name": "вал генератора", "variant": "none", "qty": 1` |

Калькулятор формирует в `parts[]` венцы `.01`, сепаратор `.02` и эксцентрики `.03`
(Д-46); правка состава меняет номенклатуру и проверку `products.check`, генераторы
`.02/.03` пока строят только состав по умолчанию. Номера `.NN` не переиспользуются,
новая позиция — в конец.

## 9. Новый генератор детали

1. `egm/cad/<имя>.py`: `build(cfg, part, row) -> PartModel` (`egm/cad/model.py`)
   и `self_test()`; рендеры `svg.render` и `step.export` общие для всех деталей (Д-32);
   альтернативный экспорт .FCStd — общий, из STEP (§7), в генераторе не нужен.
   Размеры и легенда подписываются обозначениями колонок SPEC-10.
2. Регистрация в `egm/cad/__main__.py → GENERATORS`, self_test — в `main.py`.
3. `"cad": "<имя>"` у позиции в `specs/products.yaml`.

## 10. Ограничения

В 2D пока только вид по оси; изометрия и разрезы — проекциями из STEP (CP-06).
Профиль впадин — см. §6; контур впадин в STEP — сплайном или ломаной (`--step`).
